# Barraquand–Latombe minimum-reversal search

Jérôme Barraquand and Jean-Claude Latombe, *Nonholonomic Multibody Mobile Robots: Controllability and Motion Planning in the Presence of Obstacles*, Algorithmica 10, 121–155, 1993. [Author's reading list and paper link](https://ai.stanford.edu/~latombe/cs326/2009/class12/class12.htm).

`RunPlanner('BL_Dijkstra',caseId)` implements the **one-body car planner in Sections 5 and 6**, using the two direction-indexing arrays established in the proof of Claim 2, and the six controls and length tie-break described in Section 6.3. This is an independent MATLAB/C++ implementation. It does not use Hybrid A*, an analytic goal connection, or an optimization-based repair.

## Controls and indexed search

The article controls the **front-axle** midpoint speed at `+1` or `-1` and the steering angle at `-phimax`, zero or `+phimax`. Equation (5) therefore gives rear-axle speed `v_front*cos(phi)` and yaw rate `v_front*sin(phi)/wheelbase`. For a fixed control duration `dt`, each exact rear-axle primitive has signed length `direction*dt*cos(phi)` and curvature `tan(phi)/wheelbase`. This distinction is preserved: replacing it by six equal rear-axle-length steps would change the sampled search tree. The output is a path; these unit front speeds do not prescribe the benchmark execution velocity.

Every reached state retains its continuous pose. A cell array only indexes previously accepted states; a pose is not moved to the cell center. The finite workspace is the bounding rectangle of all obstacle vertices and both task positions with 5 m padding. Each of X, Y and the full heading circle has `2^8` equal bins. Separate bit arrays record forward and reverse arrivals, as proposed in Section 6.2. A candidate whose corresponding direction/cell is already marked is discarded **before** collision checking. Otherwise it is marked on insertion into the tree. There is no state replacement, reopening, or relaxation of an already occupied cell, matching the article's indexed-tree construction.

The open heap orders paths first by reversal count, then by accumulated rear-axle length. An exact tie is broken by insertion order. The stationary initial state has no prior gear and either first direction incurs zero reversals. Zero steering is included because the permitted steering interval contains zero, as in Section 6.3. The deterministic successor order is forward before reverse, and straight before the two turns. As with other finite first-representative searches, the resulting path depends on this disclosed order and resolution; even a simple free-space query can acquire extra reversals when another pose has occupied its needed cells. The paper's asymptotic results do not certify optimality or completeness for this single finite run.

Section 6.3's goal criterion is preserved: success occurs when a **selected** open node lies in the cell containing the task goal. Its endpoint is neither snapped to the exact goal nor connected by an additional steering method. Consequently native terminal errors can be as large as one cell width in each coordinate. Heading indexing is periodic over a full revolution, and the common evaluator measures the final physical heading modulo 2 pi.

## Resolution, collision checks and resource limits

The control duration is chosen from the common grid/vehicle parameters. Let `dtheta=2*pi/256`. Choose the smallest positive **odd** integer `m` such that `m*dtheta/kappa_max >= 1.1*(cellWidthX+cellWidthY)`, and set `dt=m*dtheta*wheelbase/sin(phimax)`. Turning steps then have rear-axle mileage above the XY cell's L1 diameter, implementing the article's stated relationship between motion increments and indexing resolution. Their heading increment is an odd number of angular bins; being coprime to 256, this step avoids restricting the angular grid to a proper integer residue class. This uniformly applied parameter-selection rule is an implementation choice. An earlier noncommensurate duration exhausted its indexed trees in all three development probes, motivating the explicit angular-grid alignment. It does not change the six controls or snap any continuous reached state.

The tree-depth cap is the number of spatial/heading cells, `2^(3*8)`, as in Section 6.3. At most 33,554,432 nodes can fit in the pair of direction arrays; the node bound permits this full finite state count. Initial development caps of 2 and 8 million nodes truncated all three probes, so the final uniform bound uses the whole indexed state space after checking available memory. Large runs can require several GB of RAM. A separate 180 s native-search limit is retained. All grid/search/output work is included in planner wall time; the one-time C++ build is excluded. A resource limit is an explicit failure, not a claim that the continuous task is infeasible.

Section 6.1 expressly permits exact polygonal swept-body collision checking for a one-body car. This implementation uses that option: straight convex swept polygons, circular corner-arc/edge contacts, and reciprocal obstacle-vertex rotations against the vehicle edges. Initial overlap, contact, and excursions of the rear-axle arc outside the finite search workspace are rejected. It uses the physical benchmark rectangle and polygons directly, without a bitmap approximation or extra obstacle inflation. The geometry source is included in this planner folder.

The final primitive sequence is compressed only by merging consecutive arcs with identical curvature and direction. It is then sampled with equal mileage spacing within each gear run, at most 0.05 m, with exact cusps. Body heading, steering angle, interval gear and an exact piecewise-circular descriptor accompany the path. Curvature can jump. The public evaluator supplies independent rest-to-rest timing and execution; its success, collision percentage and strict terminal attainment remain separate from the native goal-cell flag.

## Build and tests

Run `SetupCommonParking; BuildBLDijkstra` with a configured MATLAB C++ compiler. On Windows the builder also accepts an existing Zig 0.13 executable path. The compiled module is stored under `tempdir/CommonParking/bl-dijkstra/<arch>`, or `COMMONPARKING_BL_DIJKSTRA_DIR`, outside the repository. The planner itself requires base MATLAB; the independent execution evaluator uses the separate AMPL/Ipopt runtime.

`TestBLDijkstra` verifies simple forward/reverse goal-cell arrivals, front-speed primitive lengths, curvature bounds, an impassable wall and honest node-limit failure. Release validation independently integrates all arcs, checks continuous and dense full-body safety, goal-cell membership, primitive step counts, exact cusps and reported length/reversal costs. All twelve native outcomes are retained.
