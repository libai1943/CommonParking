# Anytime predefined-space rapid optimization

Xiaoming Chen, Yueshuo Sun, Tantan Zhang, Xinwei Wang, Shengjian Xiong and Kai Cao, *An Anytime Trajectory Optimizer for Accurately Parking an Autonomous Vehicle in Tiny Spaces*, IEEE Transactions on Vehicular Technology 74(6), 2025, pp. 8772–8783, DOI [10.1109/TVT.2025.3539446](https://doi.org/10.1109/TVT.2025.3539446).

This folder implements Algorithm 1 and equations (2)–(19): the five-state bicycle OCP, differentiable frozen-sign triangle-area constraints, pose trust regions with obstacle pruning, repeated coarse-speed attachment, and minimum-cost selection from the anytime pool. The required private AMPL/Ipopt runtime is not redistributed. Hybrid A* provides the initial path, as explicitly permitted by the paper. All initialization and all optimization attempts contribute to planner wall time. Numerical-library threads are fixed to one.

## Dynamics, endpoint conditions and cost

The state is `(x,y,theta,v,phi)` at the rear-axle midpoint, with acceleration and steering-rate controls. The common benchmark body and limits are used. Speed, steering, acceleration and steering rate are all zero at both task endpoints, following equation (4). Heading constraints respect equivalence modulo `2*pi`.

The OCP is discretized by **first-order explicit Euler**, as stated at the end of Section III-C. This implementation uses 200 state/control nodes; the paper's table uses 100. Each of the 199 interval durations is a decision variable within [0.001,0.3] s, the article's reported interval limits. These bounds apply individually; the grid is not forced to remain uniform after optimization. The article does not provide its complete discrete NLP, so independent variable intervals and left-rectangle cost quadrature are disclosed transcription choices.

The objective is `TF + wa*integral(a^2) + ww*integral(omega^2)`, equation (9). The text does not supply numerical values for these two weights. This implementation sets both to 0.1, uniformly across all scenes. These are benchmark numerical choices, not claimed author values. The body uses the exact common length `Lw+Lf+Lr` and rectangular rotation. Equation (5b)'s front y-coordinate prints `Lw+Lr`, inconsistent with its x counterpart and the rectangular-body definition; the common physical rectangle uses `Lw+Lf` for both front coordinates.

## Frozen triangle signs and conservative pruning

For a reference point and a convex polygon, every triangle's signed area is evaluated at that reference. Zero has positive sign, following equation (12). Replacing each absolute area by this fixed sign times the signed area produces an affine half-space in the point coordinates. `AreaPlane` precomputes this half-space exactly. It is applied in both directions: every ego corner outside each retained obstacle and every retained obstacle vertex outside the ego rectangle. The latter is computed in the body's local frame, giving the identical signed-area expression under rigid transformation. A fixed `1e-6 m^2` area excess replaces the paper's strict inequality.

The initial reference must pass the mutual vertex-exclusion condition. If coarse resampling or a later iteration violates it, the current iteration is stopped rather than constructing an infeasible all-positive sign pattern. Previously accepted anytime candidates remain eligible, as described below. Native tests based on vertices alone can miss crossing polygons with no contained vertices; no stronger full-polygon safety claim is attached to this formulation. The common evaluator still checks complete body polygons.

The positional trust half-width grows symmetrically from `0.3*vmax` at the endpoints to `1.0*vmax` in the middle. The paper selects logarithmic growth but does not specify a normalized discrete formula. Here, with symmetric normalized progress rho in [0,1], the explicit choice is `vmax*(0.3+0.7*log(1+9*rho)/log(10))`. Every heading trust half-width is the common maximum steering angle, as in the article's simulation setting. Position and heading remain inside these boxes throughout each NLP.

For pruning, `FootprintBox` finds the exact axis extrema of every body corner over the allowed heading interval and expands them by the translation box. An obstacle is omitted only when its entire axis-aligned bounding box is disjoint from this envelope. This is a conservative, explicit implementation of Section III-C's footprint enumeration: it may retain extra obstacles, but does not drop an obstacle solely because its vertices lie outside a smaller sampled region. The article does not specify the angular enumeration grid; analytic extrema avoid an undocumented grid dependency.

## Anytime loop and reference reconstruction

The first path retains Hybrid A*'s exact gear cusps and circular geometry. Each gear run receives the common exact rest-to-rest time-optimal longitudinal profile and is sampled uniformly in reference time, following `AttachCoarseVelocity`. Initial-state/control guesses need not already satisfy the complete Euler OCP or steering-rate bounds.

After a successful NLP, the shoelace area of the closed figure formed by the old path and the reversed new path is computed exactly as described in Section III-D. The absolute signed shoelace sum can cancel for crossing paths; `TestAnytimePSRO` preserves this behavior rather than replacing it with Hausdorff distance or an unsigned polygon-union area. The convergence threshold is `0.01*NFE`, the paper's Table II rule, hence 2.0 m² for this implementation.

If another iteration is needed, consecutive duplicate positions are removed from the optimized pose sequence. Chord direction relative to body heading supplies forward/reverse labels, and heading change per signed chord supplies the coarse steering guess. The same longitudinal profile is attached again, reference poses are uniformly time-sampled, and both signs and trust regions are rebuilt. These interpolation details fill in the article's unspecified implementation of its coarse-velocity helper; they are not another optimized trajectory or a hidden search fallback.

All accepted native trajectories enter the pool. The lowest objective is returned, as in Algorithm 1. The loop stops on the path-gap criterion, a later failed solve/reference construction, or ten outer iterations. If a later attempt fails, an earlier accepted trajectory can still be returned, explicitly recording the termination and selected iteration. If the pool is empty, the planner fails. This is the article's anytime incumbent behavior, not substitution of another planner's output.

## Numerical checks and result

Each NLP uses Ipopt 3.13.4 with MA27, matching the paper's solver family, exact AMPL derivatives, adaptive barrier updates, tolerance `1e-8`, at most 2,000 iterations and 180 CPU seconds. A separate wall timeout is 390 s. Native acceptance also requires recomputed unscaled Euler, endpoint, bound, trust-region and area-plane residuals at most `1e-6` in the respective equation units. The maximum-iteration/time limits and strict-inequality tolerance are explicit finite numerical choices.

The trajectory contains the actual cumulative nonuniform timestamps and every state/control node. No interpolation is used to conceal the Euler transcription's between-node error. The independent evaluator uses the same reference interpolation and high-accuracy execution model as for the other methods. `TestAnytimePSRO` checks frozen-sign algebra, conservative rotational envelopes and the literal path-gap criterion. Release checks separately inspect the selected pool member, objective, original area predicates, physical footprint geometry and continuous input replay.

The released configuration returns ten accepted trajectories; cases 2 and 9 exhaust the NLP iteration limit. All ten pass execution optimization, but none attains the common 1 cm / 1 degree terminal tolerance. Six have nonzero executed collision percentages. Full-body native node tests are collision-free in all ten, and the maximum checked native constraint residual is about `3.25e-7`. Nevertheless, independent continuous integration of a single interval can differ from its Euler endpoint by as much as 0.0616 in a pose component. Nonuniform intervals can reach the allowed 0.3 s despite the total of 200 nodes. These are measured limitations of this disclosed transcription and parameter configuration, not a claim that the author's complete implementation has identical performance. Cases 8 and 10 return their earlier accepted incumbent after, respectively, a later NLP failure and an invalid resampled reference; those termination reasons remain in the published solver structure.
