# Customizable probabilistic roadmaps for car-like robots

Guang Song and Nancy M. Amato, *Randomized Motion Planning for Car-Like Robots with C-PRM*, IEEE/RSJ IROS 2001, pp. 37–42, DOI [10.1109/IROS.2001.973333](https://doi.org/10.1109/IROS.2001.973333). [Author's institutional publication record](https://experts.illinois.edu/en/publications/randomized-motion-planning-for-car-like-robots-with-c-prm).

`RunPlanner('CPRM',caseId)` builds the paper's two-level roadmap, customizes it to the common vehicle curvature bound, lazily validates successive shortest routes, and attempts cubic B-spline smoothing. It returns a **path**. It uses no Hybrid A* initialization, training data or manually classified parking slots. Construction, query and smoothing are all included in online timing for these independent single-case calls. The roadmap is rebuilt for each call; this release does not claim the preprocessing reuse speedups studied in the paper.

## Construction and query

1. **Control roadmap (Section 2.1).** Sample orientation-free collision-free control points. As explicitly permitted in the article, use a small disk whose diameter is less than the vehicle dimensions. Connect each point to its nearest neighbours if the edge midpoint passes the same coarse disk check. No turning-radius constraint or full edge validation is applied at this level.
2. **Approximate roadmap (Section 2.2).** Each control-edge midpoint becomes a vehicle configuration aligned along that edge. Both opposite physical headings are represented. Full vehicle footprints are checked at these configurations. For two control edges sharing a control point, connect their midpoints by a tangent circular fillet and a straight remainder, as in Fig. 2. If the outward edge angle is beta and the midpoint distances to their common point are a,b, the radius is `min(a,b)*tan(beta/2)` and the turning angle is `pi-beta`. Opposite vehicle orientations permit forward and reverse traversal; cusps may arise where consecutive connections change direction. A loose curvature threshold filters extreme connections, while their intervening footprints remain untested.
3. **Customized query (Section 2.3).** Remove connections exceeding this vehicle's maximum curvature. Connect the exact start and goal states to nearby valid roadmap configurations, then run Dijkstra. Validate edges on that candidate path with the complete rectangular vehicle; delete a failed edge and query again. Stop on a validated route, exhausted graph or declared resource bound. This is lazy refinement of the roadmap, not a fully checked roadmap followed by one search.

The paper says to attach start and goal to the roadmap but does not specify an executable attachment rule. This implementation uses shortest Reeds–Shepp connections to the nearest valid configurations, with equal forward/reverse costs, via MATLAB `reedsSheppConnection`. They are validated lazily in the same way. No separate direct start-to-goal bypass is added. This attachment choice is an adapter, not a claim about the authors' original implementation. Uniform random sampling is used; the optional medial-axis sampling mentioned in the experiments is not reproduced.

## Smoothing (Section 3.2)

For a consecutive roadmap section with one travel direction, recover its guiding control polygon from the edge midpoints and shared control points. A clamped cubic B-spline preserves the endpoints and their tangent directions. Beginning with uniform knots, compute maximum absolute curvature on each nonzero span and update the knot widths in proportion to `spanMaximumCurvature*oldWidth`, exactly the ratio proposed in Section 3.2. Retain the best maximum-curvature iterate and stop when improvement ceases or the iteration bound is reached. Tiny knot-weight floors avoid zero-length spans.

Only a curve passing regularity, common curvature and full-footprint collision checks replaces its original arc-line section. Otherwise that section keeps the already validated arcs. This fallback is explicitly allowed by the paper, whose experiments also smooth only parts of a path. The start/goal attachment curves remain Reeds–Shepp paths. **The complete output is not asserted to have globally continuous curvature:** an accepted cubic section is internally C2, while transitions to retained arcs and query attachments may have steering jumps. Cusps are preserved. The heuristic minimizes peak curvature, not path length; successful smoothing may increase length.

`Basis` implements Cox–de Boor evaluation without a spline toolbox. Each cubic span is converted to a local polynomial. Its speed extrema are found from the derivative of squared speed, and curvature extrema from `N'*V - 1.5*N*V'`, where `N=x'*y''-y'*x''` and `V=x'^2+y'^2`. Endpoints and all real in-span roots are checked. Numerical tolerances and a conservative padding apply; this is numerical polynomial checking, not a directed-rounding formal proof.

Arc-line collision checking analytically tests the complete primitive sweep, including rotating body vertices against obstacle edges and obstacle vertices against moving body edges. Cubic collision checking recursively certifies intervals with the midpoint rectangle's separating gap and an upper bound on every body point's translation/rotation. Uncertified intervals are rejected. Thus no cubic is accepted solely from finitely sampled footprints. The output is resampled uniformly by mileage within each gear run, with exact cusps and at most 0.02 m spacing. The common evaluator uses its generic interpolation for this mixed analytic path; it does not receive a circular-only geometry tag.

## Configuration and limitations

The following are disclosed implementation choices, since the paper does not supply all executable settings. The control roadmap uses 400 accepted points, up to 20,000 attempted samples, 16 nearest neighbours, and the task/obstacle bounds expanded by 3 m. The small control disk radius is one quarter of the smaller vehicle dimension. The coarse curvature threshold is 2/m and is independent of the query's turning radius. Each endpoint attaches to up to 40 valid configurations. The query allows 3,000 candidate-path attempts or 120 s. Cubic smoothing allows 20 knot updates with improvement threshold 1e-5/m, parameter speed above 1e-8, collision clearance 0.002 m and 18 certification levels. The seed is `112000+caseId`; the caller's RNG is restored. MATLAB's default numerical-library thread setting is retained.

This finite roadmap has no guarantee of solving every scene and no global-optimality claim. Its failure is not evidence that the original parking task is infeasible. Curvature jumps in retained sections can cause execution tracking errors even when the submitted geometric path is collision-free. Native planner success, evaluator success, collision percentage and terminal attainment are therefore reported separately.

`TestCPRM` verifies 200 random tangent fillets by independent integration, the B-spline partition of unity and cubic conversion, polynomial extrema against dense samples, internal spline joins and thin-obstacle rejection. Release validation additionally checks every submitted piece, path joins, exact cusp locations, endpoint poses and mileage quadrature.
